Providers & keys 供應商與金鑰

Bring-your-own-key configuration: provider records, OS-encrypted key storage, and priority-ordered routing rules.

自帶金鑰嘅配置：供應商紀錄、作業系統級加密金鑰儲存、有優先次序嘅路由規則。

Behaviour 行為

A provider records a display name, a base URL, a reference to a stored key (keyRef), and the models it serves. Routing rules match the requested model name:

MatcherMeaning
ExactOne specific model name
PrefixAny name starting with the text
Catch-allAnything — the usual final fallback

Rules evaluate in priority order and the first match wins, so specific rules belong above broad ones. Keys are stored once in the vault (Electron safeStorage, DPAPI-backed on Windows) and records hold only the opaque reference; at request time the main process resolves it, attaches the credential, discards it.

供應商紀錄有名稱、base URL、金鑰參考（keyRef）同佢serve嘅model。規則按優先次序配對請求嘅model名，第一條中就贏，所以精確規則要放喺闊規則前面。金鑰一次性存入保險庫（Electron safeStorage，Windows上DPAPI），紀錄只持有一個不透明參考；請求時主程序解析、附加、丟棄。

Configuration 設定

Provider and rule records are created, updated and deleted through the main-process configuration stores. The dedicated management tab is being built by the Providers lane; until it lands, configuration changes go through the underlying stores rather than a settings screen.

供應商同規則紀錄經主程序配置store增刪改。專責嘅管理分頁正由Providers lane興建建緊；佢未落地之前，配置變更要行底層store而唔係設定畫面。

Failure modes 失敗模式

  • Dangling key reference → explicit credential error, never a silently omitted header.
  • No matching rule → rejection naming the unmatched model.
  • Overlapping rules → only the highest-priority match fires; the lower one is inert.
  • Wrong base URL → gateway error after the request deadline.

金鑰參考懸空 → 明確嘅憑證錯誤，唔會靜靜雞唔加header；無規則配對 → 錯誤寫明邊個model；規則重疊 → 只有最高優先嗰條生效；base URL錯 → 死線之後回gateway錯誤。

Security 安全考量

Keys are encrypted at the OS level and referenced indirectly, so a leaked configuration export carries identifiers, never secrets. Log entries record that a credential was attached, not the credential. Removing a provider removes its reference; orphaned vault entries can be cleaned without exposing contents.

金鑰喺作業系統層加密而且間接引用，就算配置匯出外洩都只有識別碼、冇秘密。日誌只記「曾附加憑證」，唔記內容。刪除供應商會移除其參考；孤兒保險庫條目可以清理而唔會暴露內容。

Verification 驗證方法

Store a key and inspect the persisted record: it should contain a keyRef and no readable material. Define exact, prefix and catch-all rules, then send model names that distinguish them and confirm priority decides. Delete a rule and confirm its dependents report the unmatched-model error.

存一把金鑰再檢查紀錄：應該見到 keyRef 而且冇可讀材料。整精確、前綴、catch-all三條規則，發送能分辨三者嘅model名確認優先次序作準；刪掉一條規則，確認依賴佢嘅請求回報unmatched-model錯誤。

API builder API請求產生器

A fully graphical way to compose, save and dispatch requests through the same routing pipeline external clients use.

完全圖像化咁砌好、儲存、發送請求，行嘅係同一條外部client都會用嘅路由管線。

Behaviour 行為

The builder composes requests in structured fields — model, system prompt, messages, sampling settings, tool definitions — with a picker between the OpenAI-format endpoint (/v1/chat/completions) and the Anthropic-format endpoint (/v1/messages). Named requests can be saved, reloaded, duplicated and deleted. Sending goes through the local server, so translation, rules, credential resolution, deadlines and redacted logging behave exactly as they do for external clients. Responses render inline with timing and token usage; streamed replies render progressively.

產生器用結構化欄位砌請求 —— model、system prompt、訊息列表、取樣參數、工具定義 —— 並且可以喺OpenAI格式端點同Anthropic格式端點之間揀。具名請求可以儲存、載入、複製、刪除。發送經本地server行，所以翻譯、規則、金鑰解析、死線同遮蔽日誌全部同外部client一致。回應會連時間同用量inline顯示，串流回應逐段浮現。

Configuration 設定

Saved requests persist locally beside the rest of the app’s data. No network access happens until you press send, at which point traffic flows only to 127.0.0.1:<port> and onward to your chosen provider.

已儲存嘅請求同其他app資料一齊存喺本地。你未㩒send之前唔會有任何網絡活動；㩒咗之後流量亦只去 127.0.0.1:<port> 同你揀嘅供應商。

Failure modes 失敗模式

  • Incomplete requests (missing model, empty message list) are caught by validation before anything is sent.
  • A payload whose format does not match the chosen endpoint surfaces the same structured errors described under Routing.
  • Guard rails (body size, deadline) fail identically whether the request came from the builder or an external client.

唔完整嘅請求（欠model、空訊息）會喺發送前被驗證攔住；格式同端點唔夾就會彈返Routing嗰邊講嘅結構化錯誤；guard rails（大小、死線）無論請求來自產生器定外部client都一視同仁。

Security 安全考量

Saved requests reference providers by name and never copy API keys; credentials attach at send time from the encrypted vault. Conversation content can be sensitive, so treat the saved-request store like any local document store.

已儲存嘅請求只用名稱引用供應商，絕不複製API金鑰；憑證係發送嗰一刻先由加密保險庫附加。對話內容可能敏感，所以已儲存請求嗰個store要當一般本地文件庫看待。

Verification 驗證方法

Compose and send through each endpoint once, save and reload a named request, confirm streamed output renders progressively, and confirm a failed route produces the same redacted error an external client would see.

兩個端點各砌一次發送一次；儲存一個具名請求再載入；確認串流輸出逐段顯示；確認失敗路由彈出嘅錯誤同外部client見到嘅一樣而且已遮蔽。

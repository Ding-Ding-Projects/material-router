Routing 路由與格式翻譯

The router accepts OpenAI and Anthropic wire formats on loopback endpoints and translates between them automatically — requests, responses and streaming chunks.

路由器喺本地端點同時收OpenAI同Anthropic兩種wire format，並且自動雙向翻譯 —— 請求、回應、串流chunks全部搞掂。

Behaviour 行為

The server listens on 127.0.0.1, port 8787 by default, and serves four routes:

RoutePurpose
POST /v1/chat/completionsOpenAI Chat Completions format
POST /v1/messagesAnthropic Messages format
GET /v1/modelsModel identifiers across configured providers
GET /healthLiveness check

Translation is automatic per request: system prompts move into the Anthropic system field and back, tool calls map to tool_use/tool_result blocks, base64 images map to image_url parts, stop arrays translate both ways, and usage tokens recompute. Streaming converts Anthropic’s event sequence to OpenAI chat.completion.chunk deltas and the reverse. When an OpenAI-shaped request omits max_tokens but the destination requires it, the translator fills in 4096 and writes a note to the redacted log so the substitution is visible.

翻譯係逐請求自動做：system prompt 會搬去 Anthropic 嘅 system 欄位再搬返、工具調用映射做 tool_use/tool_result block、base64 圖片映射做 image_url part、stop 陣列雙向翻譯、用量token會重算。串流方面，Anthropic 事件序列會轉成 OpenAI chunk，反方向亦然。若OpenAI格式嘅請求漏咗 max_tokens 而目的地需要，翻譯器會補 4096 並喺已遮蔽嘅日誌度寫低一筆，等你知道有呢回事。

Configuration 設定

Host and port live in app settings and apply when the listener restarts; CORS and bearer-token authentication are independent toggles. The 10 MB body limit and the 120-second upstream deadline are fixed values in v0.1.0. Translation itself has no switches to misconfigure.

主機同埠喺app設定入面，重啟listener之後生效；CORS同bearer-token認證係獨立開關。10 MB請求上限同120秒上游死線喺v0.1.0係固定值。翻譯本身冇任何掣可以整錯。

Failure modes 失敗模式

  • Body over 10 MB → HTTP 413. Malformed JSON → HTTP 400 with a descriptive message.
  • No routing rule matches the requested model → an explanatory error naming the model.
  • Upstream unreachable or slower than the deadline → the request aborts at 120 s and the client gets an error instead of a hang.
  • Client disconnects early → the in-flight upstream request is aborted promptly.
  • Unrecognised finish/stop reasons pass through best-effort rather than crashing the stream.
  • Very long outputs can truncate earlier than expected because of the max_tokens default; the log note says when this happened.

超過10 MB → HTTP 413；JSON唔合法 → HTTP 400連說明；無規則配對到model → 錯誤訊息會寫明邊個model；上游死線一到（120秒）就中止並回錯誤俾client；client早走，上游請求即刻中止；唔識得嘅finish原因會盡力帶過而唔會整爛個stream；因為 max_tokens 有預設值，超長輸出可能提早截斷，日誌會註明。

Security 安全考量

  • Loopback-only by default; changing the bind host exposes the proxy to your network, and bearer-token auth should be enabled if you do.
  • Credentials are resolved from the encrypted vault at request time and never appear in URLs, client-facing headers or log entries.
  • Logs are redacted before storage and capped at 2,000 entries, so they cannot grow without bound.

預設只綁loopback；改咗綁址就要開bearer-token認證。金鑰喺請求時由加密保險庫解析，唔會出現喺URL、回傳header或者日誌。日誌儲存前先遮蔽，上限2000條，唔會無限長大。

Verification 驗證方法

curl http://127.0.0.1:8787/health
curl http://127.0.0.1:8787/v1/models

Then send one completion through each endpoint with "stream": true and confirm chunks arrive incrementally; route the same conversation across formats and confirm the reply parses on the other side; send an oversized body and confirm HTTP 413.

跟住用兩個端點各發一個 "stream": true 嘅completion，確認chunks逐步送到；將同一條conversation跨格式發送，確認另一邊解析正常；發個超大body確認HTTP 413。
